# Privacy Policy

**Synapse 4D & Synapse 4D Pro Pack**  
*Effective Date: October 28, 2026*

Synapse 4D is engineered on a strict **local-first** architecture. We believe personal knowledge vaults, agent conversation histories, and developmental cognitive states must remain under the complete sovereignty and physical control of the user.

---

### 1. Local Execution & Zero Cloud Telemetry

- **No Remote Telemetry:** The core engine contains no telemetry pings, background usage analytics, crash reporting daemons, or remote metric collection.
- **Local Host Execution:** All operational logic, SQLite database transactions (`.synapse/synapse_state.db`), two-phase commit logs (`.synapse/pending_writes.json`), and markdown file modifications execute strictly on your local machine (`127.0.0.1`).
- **No Third-Party Analytics:** We do not embed Google Analytics, PostHog, Mixpanel, Sentry, or any cloud tracking SDKs in either the CLI or desktop interfaces.

---

### 2. Local-Only Vector Embeddings

- **Local ONNX Inferences:** Semantic retrieval and vector indexing are powered entirely by local ONNX runtime models (via `fastembed` / local quantized transformer models).
- **Zero Embedding Transmission:** Text fragments, search queries, and memory notes are never transmitted to OpenAI, Anthropic, Google, or any external embedding API during semantic search or associative mesh computation.

---

### 3. LLM Fact Extraction & Epistemic Arbitration

- **Local-First Extraction Default:** By default, Synapse 4D is designed to extract facts and resolve contradictions using local models running on your hardware (such as local Ollama instances or deterministic rule-based fallback extractors).
- **Optional Cloud Extraction (`--allow-cloud-extraction`):** 
  - If and only if you explicitly provide the `--allow-cloud-extraction` flag along with your personal API key (e.g., Anthropic, OpenAI, or OpenRouter), the engine will call the designated external API directly from your device.
  - In this scenario, communication occurs directly between your client machine and the external model provider under that provider's own terms and privacy policy. 
  - Synapse 4D operates no intermediary proxy servers, stores no credentials, and intercepts no API payloads.

---

### 4. Pro Pack License Validation & Offline Operation

- **Validation Protocol:** For users of the commercial Pro Pack, license validation communicates exclusively with our merchant of record, LemonSqueezy (`api.lemonsqueezy.com`), over standard TLS (HTTPS) to verify key validity.
- **24-Hour Offline Cache:** License tokens are cached locally in encrypted format for 24 hours. The Pro Pack remains fully functional offline without an active internet connection during cached validation windows.
- **Transmitted Validation Data:** Only the license key string and minimal machine identifier (hashed hardware hash for seat count enforcement) are sent during activation. Your vault path, vault contents, and file metadata are never sent.

---

### 5. GDPR, CCPA, and User Data Rights

Under modern data privacy regulations (including the EU General Data Protection Regulation and California Consumer Privacy Act), users are entitled to specific rights concerning their personal data:

- **Right of Access & Portability:** Because all relational records, bi-temporal logs, and distilled facts are stored locally in standard SQLite format (`.synapse/synapse_state.db`) and plain Markdown files (`.md`), you retain 100% immediate data access without vendor lock-in.
- **Right to Rectification:** You can edit, update, or supersede any distilled fact directly via the CLI (`synapse4d review` or `synapse4d undo`), SQL queries, or through standard Markdown editing.
- **Right to Erasure (Right to be Forgotten):** You can purge all data generated by Synapse 4D at any moment by deleting the `.synapse/` directory inside your vault. No data persists on any remote server.

---

### 6. Security & Local Protections

- Synapse 4D uses process-level file locking (`filelock`) and SQLite Write-Ahead Logging (WAL) to protect database integrity against concurrent corruption.
- We recommend full-disk encryption (such as BitLocker on Windows, FileVault on macOS, or LUKS on Linux) to safeguard local vault files and SQLite databases at rest.
